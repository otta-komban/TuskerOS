## Required sign-offs before implementation

Remote-control service/API implementation is **not authorized** by this matrix. Hard gates:

1. **AEGIS-06 security approval:** device identity/key proof; challenge security; session credential/lifetime; per-request authorization interface and fail-closed behavior; revocation including active WSS; audit schema/retention/redaction; transport/TLS/exposure profile; explicit decision keeping remote approval disabled or defining a narrowly scoped approved contract.
2. **TUSKER-04 task-contract approval:** Core submission interface; trusted principal/origin propagation; task state vocabulary; idempotency scope/retention/reconciliation; authorized snapshot/redaction; event schema/sequence/cursor/replay; cancellation accepted-vs-confirmed and unknown-outcome semantics. Issue #14 response is draft v0.1 only.
3. **NOVA-02 desktop UX approval:** local pairing initiation/confirmation; device list/revoke; connection/security state; global disable; lost-device recovery; explicit private-network opt-in.
4. **PILOT-08 contract closure:** incorporate signed decisions; remove placeholders; add cancellation/global-disable contracts only after agreement; validate OpenAPI and event schemas; define versioning/errors.
5. **Integration/release review:** consult NEXUS-07 only for agreed shared service/audit integration boundaries and PHOENIX-10 for listener, TLS/certificate, packaging, upgrade, disable/recovery and clean-install behavior. These are dependencies, not approvals already requested or received.
6. **Release security verification:** execute applicable PAIR/SESS/AUTH/TASK/EVT/NET scenarios against an identified build; retain evidence and residual risks; no critical/high findings; verify loopback default, explicit opt-in, revoke propagation, no unauthorized Core mutation, idempotency/unknown-outcome recovery and secret-free diagnostics.
